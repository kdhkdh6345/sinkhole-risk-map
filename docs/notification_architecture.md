|------|-----|------|
| `sinkhole/risk/gu/{gu_code}` | 1 | 자치구 단위 (25개) |

> **QoS 선택 근거**:
> - 격자 단위 갱신(QoS 0): 유실돼도 다음 갱신(10분)에 복구 가능
> - 자치구 요약(QoS 1): 최소 1회 전달 보장
> - 3단계 긴급 알림(QoS 2): 정확히 1회 전달 필수 (중복·유실 모두 불가)

## 3. 알림 채널 비교

| 항목 | CBS (재난문자) | FCM (앱 푸시) |
|------|--------------|--------------|
| **전달 방식** | 기지국 브로드캐스트 | 인터넷 푸시 |
| **평균 지연** | 3~10초 | 0.5~3초 |
| **도달률** | ~100% (수신 차단 불가) | ~85~95% (백그라운드 제한) |
| **지오펜싱** | 기지국 반경 기반 (정밀도 낮음) | GPS/셀 ID (정밀도 높음) |
| **메시지 길이** | 최대 90바이트 | 최대 4KB |
| **사용 조건** | Stage 3 + 자치구 이상 | Stage 2 이상 + 앱 설치 |

### 권고 전략

```
Stage 2 → FCM 푸시 (앱 설치자)
Stage 3 → FCM 즉시 + CBS(재난문자) 병행 발송
         → 3단계 지속 30분 이상 → 추가 재발송 차단 (폭탄 방지)
```

## 5. 시스템 지연 시간 목표

| 단계 | 목표 지연 |
|------|----------|
| 데이터 수집 → 스냅샷 계산 | < 5초 |
| 스냅샷 → MQTT 발행 | < 1초 |
| MQTT → FCM | < 3초 |
| FCM → 단말 수신 | < 3초 |
| **총 End-to-End** | **< 12초** |

> CBS(재난문자)는 기지국 전파 지연으로 3~10초 추가 소요.  
> 총 목표: 위험 감지 후 **20초 이내** 단말 도달.
